# ТЗ: групповой выбор времени с кабинетом преподавателя

## Статус
- Draft / рабочая спецификация для реализации.

## Цель
- Дать преподавателю и ученикам простой механизм согласования времени для групповых занятий.
- Учитывать рабочие часы преподавателя как верхнее ограничение.
- Показывать не просто занятость, а готовые общие окна, которые подходят группе.
- Не перегружать интерфейс классическим тяжелым календарем, если задача решается более простым weekly-flow.

## Что должно появиться
- Публичный профиль преподавателя на сайте.
- Приватный кабинет преподавателя.
- Механика выбора времени для учеников внутри релевантных групп.
- Механика поиска общих окон по группе с учетом доступности преподавателя.

## Роли

### 1. Преподаватель
- Ведет один или несколько курсов / направлений.
- Указывает свои рабочие часы.
- Создает и ведет группы.
- Добавляет учеников, уже записанных на курсы.
- Видит, кто из учеников заполнил доступность.
- Видит общие окна по каждой группе.
- Подтверждает или публикует итоговый слот.

### 2. Ученик
- Видит только группы преподавателя по своему направлению.
- Может оставить свою доступность по неделе.
- Не может указать время вне рабочих часов преподавателя.
- Видит общие окна группы в агрегированном виде.
- Видит статус заполнения группы.

### 3. Админ
- Имеет доступ к управлению преподавателями, привязке курсов и групп.
- Может редактировать связи "преподаватель -> направления -> ученики".
- Может видеть и править проблемные кейсы вручную.

## Основные сценарии

### Сценарий A. Преподаватель настраивает свою рабочую зону
1. Преподаватель заходит в кабинет.
2. Заполняет профиль.
3. Указывает рабочие часы по дням недели.
4. При необходимости ставит исключения: отпуск, разовые блокировки, недоступные даты.
5. Выбирает направления, по которым ведет занятия.

### Сценарий B. Преподаватель собирает группу
1. Преподаватель открывает раздел групп.
2. Выбирает направление.
3. Создает новую группу или открывает существующую.
4. Добавляет учеников из числа уже записанных на курсы.
5. Видит статус по каждому ученику:
   - добавлен
   - еще не указал доступность
   - доступность заполнена
   - есть конфликт по времени

### Сценарий C. Ученик указывает свое время
1. Ученик открывает свой кабинет / страницу группы.
2. Видит преподавателя, направление и рабочие часы преподавателя.
3. Отмечает, когда ему удобно заниматься.
4. Сохраняет шаблон недельной доступности.
5. Сразу видит найденные общие окна:
   - подходит всем
   - подходит большинству
   - пока не хватает ответов

### Сценарий D. Преподаватель подтверждает слот
1. Преподаватель открывает группу.
2. Видит список найденных окон.
3. Выбирает подходящий слот.
4. Помечает его как предложенный или финальный.
5. Ученики видят выбранное время в группе.

## Обязательная бизнес-логика

### 1. Видимость групп для ученика
- Ученик видит только группы конкретного преподавателя.
- Ученик видит только группы, которые относятся к его направлению.
- Если направлений у ученика несколько, система фильтрует группы по активному курсу / текущему договору.
- Ученик не должен видеть чужие несвязанные группы.

### 2. Рабочие часы преподавателя
- Рабочие часы преподавателя являются жестким фильтром для учеников.
- Ученик не может выбрать слот вне этих часов.
- Если преподаватель изменил рабочие часы, система должна пересчитать общие окна.

### 3. Доступность ученика
- Ученик задает не текст, а интервалы по дням недели.
- В один день можно указать несколько интервалов.
- Формат для MVP:
  - день недели
  - время начала
  - время конца
  - шаг 30 минут
- Сохраняется weekly-template, а не список конкретных дат.

### 4. Поиск общих окон
- Система считает пересечение:
  - рабочих часов преподавателя
  - доступности каждого ученика в группе
  - длительности занятия
- Общие окна должны показываться в виде готовых слотов, а не только математических интервалов.
- Статусы окон:
  - подходит всем
  - подходит большинству
  - подходит части группы
- Если не все ученики ответили, система не должна помечать слот как "идеальный".

### 5. Финальный слот группы
- У группы может быть:
  - нет выбранного слота
  - предложенный слот
  - подтвержденный слот
- После выбора финального слота он должен конфликтовать с другими подтвержденными слотами преподавателя.

## Публичный профиль преподавателя

### Назначение
- Дать ученику понятную страницу преподавателя на сайте.
- Использовать ее как точку входа в согласование времени.

### Что должно быть на публичной странице
- ФИО / имя преподавателя.
- Фото.
- Направления и специализация.
- Краткое описание.
- Курсы / направления, которые он ведет.
- Формат работы.
- Кнопка перехода в кабинет / в группу для согласования времени, если пользователь авторизован и имеет доступ.

### Чего не должно быть
- Сырых внутренних данных.
- Полного списка всех учеников.
- Внутренних служебных статусов и админских полей.

## Кабинет преподавателя

### Раздел 1. Профиль
- Имя, фото, описание, специализация.
- Направления, которые ведет преподаватель.
- Контакты для внутренних коммуникаций.

### Раздел 2. Рабочие часы
- Недельная сетка доступности преподавателя.
- Возможность указать:
  - Пн 10:00-18:00
  - Вт 12:00-20:00
  - несколько окон в день
- Отдельный блок исключений:
  - отпуск
  - разовая блокировка
  - недоступная дата / неделя

### Раздел 3. Группы
- Список групп преподавателя.
- Фильтр по направлению.
- Для каждой группы:
  - название
  - направление
  - количество учеников
  - сколько заполнили доступность
  - есть ли общее окно
  - текущий подтвержденный слот

### Раздел 4. Конструктор группы
- Создание новой группы.
- Добавление учеников из уже записанных на курс.
- Привязка группы к направлению.
- Настройка длительности занятия.
- Настройка минимального числа участников.

### Раздел 5. Доска согласования времени
- Главный рабочий экран преподавателя.
- Слева:
  - недельная сетка / рабочие часы преподавателя
  - фильтр по группе
- Справа:
  - общие окна
  - кто заполнил / кто не заполнил
  - финальный выбор слота

### Раздел 6. Ученики группы
- Список учеников в группе.
- Для каждого:
  - имя
  - курс / направление
  - статус заполнения
  - дата последнего обновления доступности
- Опционально:
  - заметка преподавателя
  - статус "ожидает подтверждения"

## Кабинет ученика: согласование времени

### Что ученик должен видеть
- Преподавателя.
- Текущую группу.
- Рабочие часы преподавателя.
- Свою текущую доступность.
- Общие окна группы.
- Статус по группе:
  - ответили 2 из 4
  - есть 1 окно, подходящее всем
  - пока нет полного совпадения

### Что ученик должен уметь
- Добавлять интервалы по дням недели.
- Удалять интервалы.
- Быстро применять шаблоны:
  - будни вечером
  - после 18:00
  - только выходные
  - очистить все

## UX-принципы

### Общий принцип
- Пользователь не должен "анализировать календарь".
- Интерфейс должен отвечать на вопрос:
  - когда удобно мне
  - что из этого подходит группе

### Для ученика
- Не использовать перегруженный full-calendar как главный интерфейс.
- Лучше:
  - слева ввод своей доступности
  - справа готовые найденные окна
- На мобильном:
  - не вся неделя сразу
  - по дням / по вкладкам

### Для преподавателя
- Главный интерфейс - не профиль, а operational board по группам.
- Преподавателю важнее:
  - кто ответил
  - где есть пересечение
  - какой слот можно зафиксировать

### Цветовая логика
- доступность преподавателя: нейтральная база
- доступность текущего пользователя: синий
- частичное совпадение: желтый
- полное совпадение: зеленый
- недоступно: пусто / серый

### Что не делать
- Не смешивать в одной сетке слишком много сущностей без легенды.
- Не показывать детальную доступность всех учеников одновременно в первом слое интерфейса.
- Не делать первичную логику через длинные формы с ручным вводом текста.

## Ограничения и правила MVP

### Для первой версии
- Шаг времени: 30 минут.
- Основа - недельный шаблон, без сложной работы с календарными исключениями у ученика.
- Длительность занятия задается на уровне группы.
- Ученик видит только агрегированные общие окна и статус группы.
- Преподаватель может вручную выбрать финальный слот.

### Что можно отложить
- Голосование по слотам.
- Автоматическое бронирование слота.
- Поддержка нескольких таймзон.
- Сложные исключения по отдельным датам для учеников.
- Автогенерация расписания на месяцы вперед.

## Edge cases
- Ученик не заполнил доступность.
- Преподаватель изменил рабочие часы после того, как ученики уже ответили.
- У нескольких групп преподавателя пересекаются выбранные слоты.
- В группе недостаточно ответов для уверенного выбора.
- В группе вообще нет полного пересечения.
- Ученик состоит в нескольких группах одного направления.

## Права доступа
- Ученик не видит детальные интервалы других учеников, если это не требуется явно.
- Преподаватель видит детальные интервалы своей группы.
- Админ видит все и может корректировать вручную.

## Экранная структура MVP

### Для преподавателя
1. Список групп.
2. Страница группы.
3. Редактор рабочих часов.
4. Профиль преподавателя.

### Для ученика
1. Моя группа.
2. Моя доступность.
3. Общие окна группы.

## Приоритет реализации

### Этап 1
- Публичный профиль преподавателя.
- Кабинет преподавателя с рабочими часами.
- Группы преподавателя.

### Этап 2
- Ввод доступности учениками.
- Пересечение с рабочими часами преподавателя.
- Отображение общих окон.

### Этап 3
- Выбор / подтверждение финального слота преподавателем.
- Статусы группы.
- Уведомления и напоминания.

## Критерий успеха
- Преподаватель без помощи админа может:
  - создать группу
  - добавить учеников
  - задать рабочие часы
  - увидеть общие окна
  - выбрать финальный слот
- Ученик за 1-2 минуты понимает:
  - когда преподаватель в принципе доступен
  - как указать свое время
  - есть ли уже пересечение по группе
